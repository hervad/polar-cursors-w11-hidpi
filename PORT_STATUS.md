## (a) Busy / working spinners
- **Both are drawn in Cursors.svg**: one `Spinner` layer and one `AppSpinner` layer, each a single drawing.
- The animation exists only as PNG frames: `Spinner/Spinner0..17.png` and `AppSpinner/AppSpinner0..17.png`,
  **18 frames each, 32×32, 60 ms per frame** (Wait.conf / AppStarting.conf). One cycle = 1,080 ms.
- What moves (contact sheet, verified by eye): a **fixed white disc with a coloured bar that rotates inside it**.
  Frame 0 vertical, frame 9 horizontal, frame 17 almost vertical → 18 frames cover 180° = **10° per frame**;
  the bar is symmetric, so half a turn reads as a full spin. Disc, outline and shadow do not move.
  AppSpinner = arrow + a small disc with the same rotating bar.
- Consequence for the port: frames must be generated by rotating only the bar group of the Spinner/AppSpinner
  layer about the disc centre (angle i×10°). Rotating the whole layer would be wrong. Bar group and centre
  still to be identified in the SVG.
- 60 ms = 3.6 jiffies (not an integer): needs a mixed `rate` pattern (ADR-11 supports it) or a choice of
  3 (50 ms) / 4 (67 ms). Decide when building.

## (b) What differs between default (orange), Blue and Green
Per relative path, SHA-256 compared across the 3 folders:

| Area | Identical in all 3 | Differ |
|---|---|---|
| `Source/` top level (PNG, .conf, Build.sh …) | 118 | 0 (`Cursors.svg` only in default) |
| `Source/Spinner/*.png` | 0 | **18 (all 3 differ)**; `HueShifter.bash~` identical |
| `Source/AppSpinner/*.png` | 0 | **18 (all 3 differ)** |
| `cursors/` compiled Xcursor | 63 (+25 symlinks, same targets) | **2: `watch`, `left_ptr_watch`** (the two animated) |
| root | `COPYRIGHT~`, `index.theme~` | `index.theme` (Name only) |

- **The variants differ ONLY in the colour of the spinner bar.** All static cursors are identical (white/grey;
  `Arrow.png` has no coloured pixels).
- Spinner PNGs: alpha channel **identical** across variants (same shape); median hue of coloured pixels
  in frame 0: default ≈ 14° (orange-red), Blue ≈ 194°, Green ≈ 89°. → consistent with a hue shift.
- `HueShifter.bash~` inference: **partly confirmed.** The *result* is a hue shift (same alpha, only hue moves).
  But the script as written cannot have produced it: `mogrify modulate 0,0,HUE` lacks the `-` before
  `modulate`, uses the literal `HUE` instead of `$HUE`, and `0,0` would set brightness and saturation to 0
  (black). It is a broken draft (also a `~` backup); the real method is unknown.
- For the toolkit: one SVG + a `recolor` map on the bar's colour(s) for Blue and Green. Exact hex values still to
  be read from the SVG and checked against the shipped PNG colours.
